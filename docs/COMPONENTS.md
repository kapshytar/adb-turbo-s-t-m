# Компоненты: куда идут правки

**Короткий ответ: правка файлового менеджера — коммит в ЕГО форк, не сюда. Сюда — только новый pin.**

## Почему не «внутрь»

Этот репо под **MIT**. `ADBFileExplorer`, `filedroid` и `adbfs-rootless` — под **GPLv3**. Скопировать
их исходники сюда — значит сделать GPLv3 всю объединённую работу и потерять MIT на собственный код.
Поэтому здесь нет и не будет их исходников: только указатель на них.

Ссылаться на GPL-репозиторий — не распространение GPL-кода. Копировать его файлы — распространение.
Вся конструкция построена на этой разнице.

## Кто где живёт

| Компонент | Лицензия | Оригинал | Наш форк | Где живут наши правки |
|---|---|---|---|---|
| ADBFileExplorer (Python/Qt) | GPLv3 | Aldeshov | kapshytar | коммиты в форке |
| FileDroid (Flutter) | GPLv3 | andrisasuke | kapshytar | коммиты в форке |
| adbfs-rootless (C++) | GPLv3 | spion | **нет** | `patch/*.patch` в этом репо |

Два браузера — осознанно: ADBFileExplorer даёт EXIF-превью, FileDroid активно развивается и
собирается в CI. Оба запускаются из трея.

`adbfs-rootless` — исключение: своего форка нет, поэтому единственный носитель правок — патчи.
Для двух браузеров патчи НЕ заводим: их правки уже есть коммитами в форках, второй носитель
только расходится с первым.

## Рабочий цикл

```bash
# 1. правим компонент — в его собственной папке
cd ~/PhoneAsExtStorage/ADBFileExplorer
git commit -am "..."          # коммит идёт в форк, не в adb-turbo-s-t-m
git push fork HEAD            # remote 'fork' = kapshytar; 'origin' = чужой оригинал!

# 2. фиксируем в этом репо, какая версия компонента теперь «наша»
cd ~/PhoneAsExtStorage/public-repo
scripts/components.sh pin     # перепишет components.conf
git commit -am "pin ADBFileExplorer"
```

Осторожно: в форках **`origin` указывает на репозиторий чужого автора**, а наш — `fork`.
Голый `git push` уедет к апстриму и отобьётся по правам. Всегда `git push fork`.

## Команды

```bash
scripts/components.sh status   # что стоит, на чём стоит, где разошлось с пином, что не запушено
scripts/components.sh sync     # поставить недостающее и перевести на пины (свежая машина)
scripts/components.sh pin      # записать текущие HEAD'ы в components.conf
```

`status` отвечает на вопрос «этот коммит вообще есть на форке» (`git branch -r --contains`), а не
«совпадает ли с текущей tracking-веткой» — второе врёт, когда локально сидишь на старой
feature-ветке (ловилось на filedroid: 10 «непушенных», которые все лежали в `fork/main`).

Манифест — [`components.conf`](../components.conf) в корне репо.
